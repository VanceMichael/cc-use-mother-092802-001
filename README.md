# 央企人工智能资源普惠开放治理

管理人工智能模型、数据和算力资源的申请、评审、配额与公平开放。

## 参与方与事实

主要参与方包括社区运营人员、央企资源提供方、开发者（申请人）及其所属机构、安全审核人员、行业场景负责人、独立评审人员、审计人员。领域资料记录以下已经确认的事实：

- 人工智能焕新社区2.0汇聚超过3万个模型和4000个数据集
- 社区建设具身智能和人工智能安全等专区
- 平台支撑3万多名开发者开展应用创新
- 申请、场景优先级、算力额度、数据许可、安全专区此前分散在不同台账，资源紧张时难以证明开放机会公平
- 工业一线、安全研究、公共服务三类项目允许采用不同的开放规则
- 停机期间存在即将到期的授权、未完成评审和待核对用量，需要在恢复后接续

## 业务约束（v2，共十二条）

- **资源与许可版本**：模型/数据集按版本登记，授权引用具体版本；重复申请返回原结果（幂等），内容变化进入新版本。
- **申请评审**：机构→开发者→项目目标→资源版本→许可→算力需求→评审依据→实际用量八环节连续留痕；工业一线、安全研究、公共服务三类轨道规则分治；规则变化只影响未决申请，已批额度保留当时依据；申请人不得审批本人例外；评审人员最小知情。
- **算力配额守恒**：领取、释放、延期在总额度内守恒，释放即时回流，延期不增额度，挤占与回流可查。
- **敏感信息裁剪**：最小知情裁剪字段，存在性遮蔽保证无权者无法通过搜索、计数、报错差异推断敏感资源是否存在。
- **公平性解释**：可解释任一项目的获批/拒绝原因、所用资源版本、是否挤占他人额度，并按群体汇总普惠达成；停机后接续到期授权、未决评审与用量核对。

完整不变量（C1–C12）与记录链路定义见 `docs/domain-rules.md`。

## 资料结构

`contracts/context.schema.json` 描述资料结构（v2 起包含 `record_chain` 记录链路、`rule_tracks` 三类轨道、`continuity` 停机接续），`fixtures/context.json` 提供不含真实身份信息的示例，`src/ai_resource_context.py` 负责读取和校验这些资料（字段完整性、约束标签覆盖、链路连续编号、轨道与接续对象齐全、无真实身份痕迹）。
